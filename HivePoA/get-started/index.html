Get started

Current tip: checking the signed index… (supervised one-PC beta). Any release the signed index marks revoked is withdrawn and not approved for testing; Releases lists each one with its recorded reason. GitHub is a byte mirror only — verify SHA-256 before running.

Windows will probably warn you about this file: it is not code-signed. Expect “isn’t commonly downloaded” in the browser and possibly “Windows protected your PC” on first run. Verify the SHA-256 first — once it matches, you have proof it is the exact file the operator published.

  1. Prefer the authenticated three-file handoff when the operator issues one; otherwise use the signed Pages tip shown on Download and verify its SHA-256 on Verify.
  2. Two channels carry releases: GitHub Releases and IPFS. They are signed against the same release index, but a given build may publish the package to one and only signed metadata to the other — Download says which is which. Whichever you use, the SHA-256 you verify is the same.
  3. Confirm the pinned channel-index fingerprint locally; the webpage alone is not the trust root.
  4. Verify filename, bytes, and SHA-256 before running anything.
  5. Storage stays off until you deliberately opt in inside the desktop app.

This page never auto-downloads packages and never silently switches mirrors. IPFS-first signed artifacts plus an independently authenticated handoff are the authority.

Friend card (Forever Drive + voluntary pins)

These steps work today on their own. The app runs its own embedded coordinator, so it needs no enrollment packet to contribute storage:

  1. Download the current tip checking the signed index… from Download (or operator handoff), verify SHA-256, and launch.
  2. Opt in Forever Drive at 20% inside the app.
  3. Browse → pin videos you choose. Voluntary pins share the same 20% quota; Forever Drive reservations keep priority. No compute, Brain, Neura, or paid rewards are claimed from local pins alone.

Joining the shared pool is not available yet

Pool assignment needs a private enrollment packet issued against a live HTTPS coordinator, and no such coordinator is published today. Until the operator announces one and issues you a packet, the tray's Copy Enrollment Request and Import Private Enrollment items have nothing to register against and will fail closed rather than pretend. That is expected, not a fault in your setup.

readyForPool stays truthful throughout — embedded-only mode is deliberately not pool-ready, and the app will keep saying so until a real coordinator assigns work.

If the app does not open

Storage Preview only recovers a verified owned leftover on its local port. A healthy foreign or unverifiable listener is never force-killed. If an older Storage Preview window is already open, use the system-tray icon — a second double-click focuses that window.

If another unrelated program blocks the local preview port, close that program and open Storage Preview again.
